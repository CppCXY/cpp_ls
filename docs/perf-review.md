结论
主要问题不是“C++ 单文件天然需要几十秒”，也不是完全没有缓存。最突出的可避免成本是：可见依赖闭包遍历中，对 HashSet 做了大量线性扫描；同一个冷闭包还可能被并发计算多次。 此外，空诊断仍会触发闭包检查，缓存失效和后台调度也有进一步优化空间。

昨晚的提交方向是有效的：40b69b56、6ed0a8f5 改善了闭包和成员列表复用，1c7f68db 优化了宏查询。问题主要集中在冷路径和并发重复工作，这些提交不能单独解决它们。

实测证据
真实运行日志显示，工作区从开始分析到报告索引完成约 43 秒。日志中的最长更新持锁时间为 43 毫秒，说明当前长耗时不能简单归咎于锁；这也不代表请求排队和计算时间都只有 43 毫秒。

在隔离副本中，打开目标文件后不主动发送 hover、completion 或诊断请求，前 50 秒服务器消耗约 95.4 CPU 秒，采样峰值约 341% 单核，内存升至约 813 MiB。这段时间包含工作区索引，不能全部归因于单文件诊断，也尚不能证明存在死循环。

同一构建条件下，只在实验副本中把 uncertain 的两处线性查找改成哈希查找，得到以下单次对照。索引结束、磁盘缓存已热，但进程内可见闭包是冷的；两个服务器顺序运行：

重定义，返回空列表	20.48 秒	1.55 秒	两边输出哈希一致
参数类型检查	27.48 秒、50.00 CPU 秒	2.45 秒、3.02 CPU 秒	两边均 3 项，输出哈希一致
参数检查中，两次并发的冷闭包遍历各涉及该实现记录的 857 个贡献文件，原版各耗约 23.84 秒，实验版约 0.32–0.39 秒。857 不等于真实编译器的权威头文件依赖数。

热缓存确实有价值：空诊断重复请求约 9 毫秒。另一次仅启用重定义规则的实验里，追加注释后的诊断为 345 毫秒，可见闭包缓存仍命中；因此不能说每次编辑都会重走整个闭包。

目标文件的原始语法解析约 15.7 毫秒；它不包括头文件预处理和语义分析，仅用于说明瓶颈并非这 342 行文本的基本解析。默认诊断在隔离副本中曾等待 120 秒仍未返回；实验版另一次完整默认诊断仍需约 4.16 秒，所以两处哈希查找不是全部问题。

架构分析
C++ 确实需要上下文。 宏、条件编译、头文件及编译选项会改变同一段文本的含义；结果只能在上下文兼容时复用。但这不能解释哈希集合的线性查找和相同工作的并发重复。
明确的算法热点。 mark_uncertain 和 is_uncertain 对 HashSet 使用 iter().any()；实验表明换成 contains 能显著降低此次冷闭包成本。
缺少同键进行中工作的合并。 the_visible_walk 查询和写入缓存时加锁，但 miss 后在锁外独立计算；后台诊断预热和前台请求可以撞上同一冷闭包。本次 trace 确实观察到了两份并发遍历。
空结果也触发昂贵门槛。 诊断发布即使没有语义 finding，也无条件检查闭包是否就绪。这解释了“什么诊断都没有，第一次仍耗几十秒”。
有缓存，但复用粒度不够。 项目已有磁盘 summary、语法视图、宏环境、闭包、类型和定义缓存；不过诊断 memo只有一个槽，键还包含全局 store revision，多个文件交替访问或无关文件失效都可能造成重算。编辑处理也会丢弃当前文件的 summary 和 cooked 结果，但已通过指令签名避免部分依赖失效。
后台工作会和交互争资源。 索引最多使用 8 个工作线程，诊断预热和按需读取还会继续运行；“索引完成”不等于 CPU 工作全部结束。实际项目没有找到编译数据库，会使用默认编译环境和模糊 include 解析；这可能影响依赖范围和准确性，但其独立性能影响尚未量化。
建议优先级
先修两处哈希查找，补充宏、条件分支和诊断结果回归，再测完整默认诊断，不把这个优化当作全部修复。
无语义 finding 时跳过就绪门槛，同时保留语法错误和模块备注；对同一文件、同一版本/依赖状态的冷闭包和诊断计算做 single-flight，并正确处理取消与版本变化。
将诊断缓存改为按文件和依赖版本管理，缩小全局失效范围；对头文件结果按宏环境和编译选项复用，避免使用可能过期的语义结果。
限制和分时后台索引、预热，优先保证打开文件和交互请求；为项目生成并配置 compile_commands.json，再分别比较依赖闭包、CPU 和正确性。
建立 release 性能回归：统计冷/热延迟、CPU 秒、闭包构建次数和缓存命中。当前 CI 默认运行 debug 测试，而延迟测试在 debug 下提前跳过；真实项目探针也默认忽略。
**验证边界：**上述对照是单次样本，不是 P95 或所有项目的性能保证。更早在不同二进制和索引时机下曾出现诊断数量 0 与 3 不一致，原因未证实；严格对照中结果一致，但仍需专门验证诊断稳定性。实验仅在隔离副本进行，原仓库未修改，临时文件已清理。
